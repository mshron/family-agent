# Phase 1 — Feel test: what is running, and how to use it

Status: **deployed and verified** on the code box (2026-10-03). The design
lives in `docs/memos/hetzner-consolidation.md` (Phase 1 section); the
rules that make running bare acceptable are listed there and repeated
below.

## What is running

On the code box (`128.140.54.129`), under `/opt/family-agent/`:

| Piece | What it is |
|---|---|
| `fa-gateway` container | The Zulip↔pi bridge. Long-polls one Zulip event queue; one pi session container per (stream, topic); injects memory files into every message; posts replies; handles `/new` `/compact` `/stop` `/model` `/stats`. |
| `fa-<hash>` containers | One per active conversation: `pi --mode rpc` with full tools, git, the `auto` virtual model, and the search MCP (Brave tonight). Disposable; recycled after 30 min idle. |
| `workspace/` | The scratch channel's git repo: `AGENTS.md` conventions, `notes/`, `docs/`, `memory/`. Sessions commit here. |
| `sessions/` | pi session files (durable conversations) + `gateway-index.json`. |
| `.env` | Secrets, mode 600. Generated by `deploy/push-secrets.sh` from local sources. |

The Zulip bot is the existing "Nanobot" bot user in your org, listening
on the private stream **`scratch`**. The old nanobot's three Fly apps were
already suspended, so nothing else consumes that user.

## Morning steps (5 minutes)

1. **Join the stream.** In Zulip, join `scratch` (it is private; browse
   streams → scratch, or ask and I can add you if you give me your Zulip
   email — set `ZULIP_OWNER_EMAILS` in `/opt/family-agent/.env` and
   restart the gateway). A "Test Bot" user is also in it; my overnight
   test messages are in topics `hello`, `mcp-test`, and `handoff-test`.
2. **(Optional) flip search to Kagi.** In `/opt/family-agent/.env` set
   `SEARCH_PROVIDER=kagi` and `KAGI_API_KEY=<key>`, then
   `docker restart fa-gateway` (new session containers pick it up).
3. **Chat.** Every topic in `scratch` is its own conversation. Try a
   coding question, ask it to search something, write a note, then `/new`
   and ask about it again.

## Using it

- Messages: anything you post in a scratch topic goes to that topic's
  session, with memory files prepended.
- `/model auto low|high` — GLM-5.3-flash vs strong GLM-5.3 for the
  thread. `/model flash` and `/model strong` set the physical model
  directly. Default is `auto low`.
- `/stats` — tokens and cost for the topic's session.
- `/new` — the session writes a handoff note to `notes/`, then starts a
  fresh conversation. Memory and workspace carry over.
- `/compact` — compact the conversation in place.
- `/stop` — abort the current run.

## The rules that make running bare acceptable

No email, no finance repo, no deploy keys, no browsing MCP. Kagi/Brave
results are the only untrusted text entering a session. When Phase 2
lands, rotate everything Phase 1's sessions could have seen: the Zulip
bot key and the OpenRouter key in their environment. (One note: while
debugging the Zulip event API, the bot key appeared in base64 in a
terminal transcript — another reason to rotate at Phase 2.)

## Known Phase 1 limitations (by design or accepted)

- Sessions run with real credentials in their environment; no proxy, no
  permission gates, no log service (Phase 2).
- The gateway posts only the final reply text; no streaming updates in
  the topic (streams well enough for chat-style use).
- If the box reboots, `fa-gateway` restarts (compose `unless-stopped`)
  and conversations resume from their session files; live session
  containers are recycled lazily.
- Replies over 9000 chars are truncated with a pointer to the workspace.
